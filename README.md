# Austin FC Fan Assistant

Public test site: **https://austin-fc-fan-assistant.vercel.app/**

A mobile-first stadium assistant for concessions, transportation, stadium policies, accessibility, ticketing guidance, weather, and Austin FC information. It answers common requests directly from a checked knowledge snapshot and uses a separately hosted language model for flexible questions. Codex is the development tool, **not** the model that runs the deployed chatbot. The assistant cannot purchase tickets or access a fan's private account.

The interface keeps information browsing inside the site: [in-site guides](https://austin-fc-fan-assistant.vercel.app/guide?topic=sources) contain the copied Q2 stadium map, published vendor locations, section directory, policies, transit guidance, schedule, roster, news, ticket steps, and current weather. [Questions to try](https://austin-fc-fan-assistant.vercel.app/try) separates knowledge-base, model-assisted, and live-weather examples. Official provider addresses remain in the API metadata for traceability, but fan-facing guide and source cards route to local pages. Transactions remain outside the preview.

The desktop menu opens as a compact icon rail and can be expanded with its top button; that choice persists in the browser. **Share chat** creates a read-only snapshot in the public Blob store and copies an unguessable `/share/...` link. Anyone with that link can see the snapshot, personal contacts, credentials, addresses and map origins are scrubbed server-side. A redacted preview and review checkbox precede publishing; fans must check for names or other details the scrubber may miss. Further conversation does not change an existing snapshot; use **Create updated copy** for a new link.

## Operations

- Hosting and builds: Vercel project `austin-fc-fan-assistant` under Joe's projects, connected to this GitHub repository. Pushing to `main` runs the cloud build and deploy.
- Knowledge: `scripts/ingest.py` retrieves current official pages, validates a minimum number of stadium documents/vendors, beverage products and club records, and produces `data/knowledge.json`. The daily `Refresh stadium knowledge` GitHub Action publishes a versioned snapshot to Vercel Blob. The server reads its `latest.json` pointer and falls back to the bundled snapshot if retrieval fails. Run that workflow manually after an important official update.
- Sources: [Q2 Stadium](https://www.q2stadium.com/), [Austin FC](https://www.austinfc.com/), [CapMetro](https://www.capmetro.org/special-events/Q2), and the [National Weather Service](https://www.weather.gov/documentation/services-web-api). The [public sources page](https://austin-fc-fan-assistant.vercel.app/sources) shows the currently checked snapshot. The Satisfi exports informed vocabulary and evaluation cases, but historical replies are not treated as current authority.
- Models: server-side Vercel AI Gateway tries `openai/gpt-5.4-mini`, then `openai/gpt-5.4`, a bounded failure response if both providers fail. Paid Gateway credit was enabled and an actual `gpt-5.4-mini` response and official-source web search were verified on September 25, 2026. Auto-reload is disabled, so monitor the credit balance. Known policies and services use reviewed deterministic routing; unfamiliar questions can use `gpt-5.4-mini` to interpret and split requests; supported common answers are then composed from checked data. If that classifier fails, bounded local routing handles recognized requests. Safety always bypasses the model. Flexible answers use generation; weather and club lookups use their respective real services. Codex's hosted code-execution harness is not part of the fan chat runtime.
- Storage: one public Blob store for versioned knowledge and evaluation results; one private Blob store for feedback. `BLOB_READ_WRITE_TOKEN`, `KNOWLEDGE_BLOB_URL`, `FEEDBACK_READ_WRITE_TOKEN`, `FEEDBACK_STORE_ID`, and `CRON_SECRET` are server-only Vercel environment variables. `CRON_SECRET` is also a GitHub Actions secret for protected publishing. Never commit these values.
- Monitoring: `/api/health` reports snapshot age and counts. Vercel logs record route, latency, answer length, model token usage, and retrieval failures without full fan prompts. Feedback is saved privately and can be reviewed through authenticated `/api/feedback` GET by receipt; no public feedback export exists.

## Verification and updating

The `Cloud checks` GitHub Action builds, runs unit tests, a fixed 120-case offline evaluation, and desktop/mobile browser checks. The `Production acceptance` action tests those same 120 cases against the **public production API** and, if at least 90% pass with no critical failures, saves the report in Blob at `evaluations/latest.json`. Run it after a deployment or material content change. Its report artifact includes each answer and source for review.

To change content, edit the ingest rules or reviewed structured data, then run the refresh workflow and review `/sources`, `/api/health`, and a production acceptance run. `data/club-schedule.json` contains the reviewed published home and away fixtures; the assistant selects the next future fixture at request time and never reuses a past featured match. Update the file when the club changes kickoff details or publishes new fixtures. Weather is retrieved live from NWS, with a short cache. The stadium map is linked for locations; zone-based proximity is approximate, not a walking-time estimate.

The fixed 120-question check now resolves its next-home-match expectation from the schedule instead of naming a permanent opponent. `npm run eval:conversations` exercises paraphrased multi-turn fan chats from historical Satisfi wording and the live test conversation. The production acceptance workflow repeats those chats against the public API and uploads `conversation-human-review.csv`; a person should mark answer correctness and whether each linked source supports the claim before using the results as a quality claim. Historical bot responses are never treated as current facts.

## Later native-app integration

The website is the proof of concept. The Austin FC/Yinzcam app can embed it in a web view or call `POST /api/chat` from a native chat interface. The API takes `{ messages: [{ role, content }], context: { section?, dietary?, language?, event? } }` and streams newline-delimited JSON events: `meta` (route, sources, cards, updated context), `delta` (answer text), and `done`. The native app should store the returned context per fan session, offer a reset, and use official app deep links for ticket transactions. Before a broader launch, agree on brand review, event data integration, privacy retention, traffic limits, and any account-specific capabilities with the app team.

## Answer-quality regression coverage

`data/redteam.json` includes the exact UT/7:30 → concert-parking sequence. Assertions check the requested answer, exclude unrelated modes/policies, verify sources and actions, and cover bilingual safety, dietary negation, product-specific drinks, accessibility, multiple ticket roles, refund domains and provider failures. `tests/quality.test.ts` additionally checks context changes and forced provider failure. Public browser tests include real Blob-backed sharing in a fresh second browser context.

The original 120 questions remain fixed. Their expected results were corrected where they previously required the word “bar” for soda/product questions or required Q2's Will Call source for Austin FC mobile transfer instructions. The correct product/location and the source supporting the actual answer are required instead. Automated scores alone are not a human quality judgment; full deployed transcripts must also be read.

Parking lot addresses and the map are reviewed in `data/parking-reviewed.json`. Leave-by calculations use a capped live route estimate when available, or a travel duration supplied by the fan; there is no assumed trip duration. Changing origin, mode or event clears an old duration. Published location conflicts are logged for staff. Fan answers use reviewed locations or Guest Services directions.

## October red-team repair

See [the repair and handoff report](./OCTOBER-REDTEAM.md) for the issue-by-issue changes, verification evidence, internal submission/approval steps, routing costs and enforced limits. `data/october-redteam.json` supplies the reported prompts and extrapolated variants; the production red-team workflow saves complete transcripts for review.

Known safety categories are a hardcoded bilingual table in `lib/safety.ts` and return before model planning/generation. The six categories are self-harm, medical, lost person, lost item, harassment and evacuation/severe weather. Current fan wording selects language each turn. The assistant covers Q2 only, in English or Spanish.

The application enforces 30 chat requests/client/minute (safety bypasses throttling), 10 shares/client/hour, 30 feedback requests/client/hour, 1000 paid model calls/day, $25/day in conservative AI reservations and 200 routing-provider calls/day, using atomic Blob ETag writes across instances. AI budgeting does not cap Vercel hosting/storage charges. Provider failures retain reservations. Routing caches estimates for 15 minutes and public-place geocoding across requests. Keys and raw prompts are never written to public logs. Private scrubbed diagnostic records support reproducible fallback/template reviews through `/api/diagnostics` with reviewer credentials.

## Independent safety and fan regression suite

`data/creative-redteam.json` adds independently written English/Spanish incident stories, ordinary negative controls, Unicode/casing mutations, malicious instruction wrappers, and multi-turn fan conversations. `tests/creative-redteam.test.ts` runs these through the real prepare/stream paths with providers offline; the live runner `scripts/creative_redteam_live.py` checks the actual NDJSON API and preserves complete transcripts and failures. Fixed safety route/planner, emergency actions, current-turn language, relevant sources, verification timestamps, transaction boundaries and ordering handoffs are assertions, not model-graded opinions. Mechanical variants are reported separately from independently authored stories.
